# sunlit Skill 使用说明

`/sunlit` 是一个 Claude Code 技能，让你用自然语言驱动 sunlit 日照分析工具。
分析结果基于你提供的真实数据文件，适合设计阶段的场地日照评估。

---

## 使用方式

在 Claude Code 对话中，**附上数据文件**，然后输入命令：

```
/sunlit 分析这个地块冬至日 09:00-15:00 的地面日照，达标阈值 2 小时
```

---

## 需要准备哪些文件

### 必须提供

| 文件 | 格式 | 说明 |
|------|------|------|
| 场地边界 | GeoJSON Polygon | 分析范围，必须是**投影坐标系**（如 EPSG:27700、EPSG:3857），不能是经纬度 |
| 周边建筑 | GeoJSON / CityJSON | 现状建筑体量，GeoJSON 需包含 `height` 属性 |

### 可选提供

| 文件 | 格式 | 说明 |
|------|------|------|
| 拟建方案 | GeoJSON / CityJSON | 用于评估方案建成后对场地日照的影响 |
| OBJ 文件 | .obj + meta.json | 来自 SketchUp 或其他建模软件的体量模型 |

### 数据来源建议

- **场地边界 / 建筑底面**：从 QGIS、ArcGIS、城市 GIS 平台导出为 GeoJSON，确保使用投影坐标系
- **建筑体量**：从 SketchUp 导出 OBJ，或由建筑师提供 CityJSON
- **建筑高度**：GeoJSON 的 feature properties 中需有 `height` 字段（单位：米）

### 如果数据混在一起怎么办

从 GIS 平台导出时，场地边界和周边建筑有时在**同一个 GeoJSON 文件**里。直接把这个文件给 Claude 即可，并说明哪个 feature 是场地边界：

```
/sunlit 分析这个场地的冬至日照，城市是上海

附件：
- all-data.geojson（建筑和场地边界混在一起，name="site-boundary" 的那个是场地边界）
```

Claude 会自动拆分成 `site.geojson` 和 `context.geojson` 两个文件，再进行后续处理。

---

## 命令示例

### 场地现状分析（无方案）

```
/sunlit 分析伦敦这个场地的日照现状

附件：
- site.geojson（场地边界）
- context.geojson（周边建筑，含 height 属性）
```

### 方案影响分析（有拟建建筑）

```
/sunlit 对比分析方案建成前后场地日照变化，日期冬至，阈值 2 小时

附件：
- site.geojson
- context.geojson
- scheme.geojson
```

### 使用 OBJ 体量模型

```
/sunlit 用这个 OBJ 模型分析场地日照

附件：
- scheme.obj
- meta.json（OBJ 分组与建筑属性的映射）
- site.geojson
```

---

## 你需要告诉 Claude 的信息

附上文件后，还需要说明：

| 信息 | 示例 |
|------|------|
| 城市 / 地点 | 伦敦、东京、上海（用于计算太阳位置） |
| 分析日期 | 2026-01-21、冬至、夏至 |
| 时间段 | 默认 09:00–15:00 |
| 达标阈值 | 默认 2 小时 |
| 网格精度 | 默认 3m，精细分析用 2m |

---

## 输出内容

| 文件 | 内容 |
|------|------|
| `heatmap.png` | 地面日照热力图（橙框 = 场地边界，颜色 = 日照时长） |
| `analysis.json` | 完整数据（每个评估点坐标、日照时长、达标情况） |
| `summary.md` | 统计摘要（达标率、达标面积、平均日照时长） |
| `metadata.yaml` | 分析参数与输入文件记录 |

Claude 还会在对话中给出**自然语言设计建议**，说明哪些区域日照不足、原因是什么、如何优化。

所有文件保存在 `sunlit-output/<城市-日期>/` 目录下。

---

## 注意事项

- 场地边界必须使用**投影坐标系**，不能直接用经纬度（工具会报错拒绝）
- 建筑模型为 LOD1（方盒子体量），不含屋顶坡度、挑檐等细节
- 本工具面向**设计阶段参考**，不用于居住建筑报建或法律用途的满窗日照分析
- 如需正式报建，请使用专业日照分析软件
