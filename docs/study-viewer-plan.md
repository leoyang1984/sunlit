# Study Viewer Development Plan

Status: planning

This plan describes a deterministic local HTML viewer for `sunlit` study outputs.

The viewer is not an AI image enhancement step. It is a safe presentation and review layer that embeds deterministic outputs without modifying analysis pixels or numeric data.

## Product Goal

Make each study output folder easy to review without requiring users to inspect separate files manually.

The viewer should help users:

- preview rendered heatmaps at different image sizes;
- switch between baseline and with-scheme results;
- read the deterministic Markdown summary;
- inspect metadata and raw JSON;
- keep a clear boundary between analysis data and presentation layout.

## Integrity Boundary

The viewer may format, arrange, and display outputs.

The viewer must not:

- recolor or regenerate `heatmap.png`;
- edit the heatmap image pixels;
- infer new numeric conclusions;
- replace `analysis.json` as the source of truth;
- present results as permitting, legal, code-compliance, or full-window sunlight analysis.

The viewer should explicitly state:

```text
Heatmap pixels are embedded from deterministic output without AI or style edits.
Numeric judgment remains analysis.json + heatmap.png.
```

## Target Output Structure

For a full DXF study:

```text
sunlit-output/<study>/
├── presentation.html
├── site.geojson
├── context.cityjson
├── scheme.cityjson
├── conversion_report.md
├── baseline/
│   ├── analysis.json
│   ├── heatmap.png
│   ├── metadata.yaml
│   └── summary.md
└── with-scheme/
    ├── analysis.json
    ├── heatmap.png
    ├── metadata.yaml
    └── summary.md
```

For context-only or scheme-only studies, the viewer should gracefully show only the available run.

## Viewer Requirements

### 1. Adaptive Heatmap Preview

The map panel must work for different heatmap dimensions and site shapes.

Required behavior:

- fit heatmap inside the available viewport with `object-fit: contain`;
- preserve original image aspect ratio;
- avoid cropping the heatmap;
- support large and small output images;
- provide simple view controls:
  - fit to view;
  - 100%;
  - optional zoom in/out;
- provide a link to open the raw `heatmap.png`.

### 2. Report and Data Review

The viewer should include tabs or segmented controls:

```text
Map | Summary | Metadata | JSON | Conversion
```

Expected behavior:

- `Map` shows the selected run's `heatmap.png`.
- `Summary` renders the selected run's `summary.md`.
- `Metadata` displays `metadata.yaml` in a readable preformatted block.
- `JSON` displays formatted `analysis.json`.
- `Conversion` displays `conversion_report.md` when available.

### 3. Run Switching

The viewer should provide run buttons:

```text
Baseline | With Scheme
```

When switching runs, update:

- heatmap;
- study setup;
- key statistics;
- summary;
- metadata;
- JSON.

If only one run exists, hide or disable the missing run button.

## Implementation Strategy

Prefer a self-contained static HTML file generated by `sunlit`.

First version:

- generate `presentation.html` from Python;
- inline the minimal JSON/Markdown/YAML text needed for display;
- reference heatmap images by relative paths;
- use plain HTML/CSS/JavaScript, no external CDN;
- work offline from the output directory.

Avoid relying on `fetch()` for local files in the first version because `file://` browser restrictions vary.

## CLI Integration

Add viewer generation to `sunlit study` after conversion and analysis succeed.

Possible future option:

```bash
sunlit study sunlit.yaml --output sunlit-output/my-project --no-viewer
```

Do not add auto-open browser behavior by default. Printing the path is enough:

```text
Wrote sunlit-output/my-project/presentation.html
```

## Testing Plan

Add tests for:

- viewer file is written by `sunlit study`;
- viewer includes available run names;
- viewer includes key statistics from `analysis.json`;
- viewer references heatmap paths without embedding or modifying image pixels;
- context-only study hides or omits with-scheme controls;
- with-scheme study includes both baseline and with-scheme controls.

Optional visual QA:

- render the HTML with Playwright when browser binaries are available;
- screenshot desktop and narrow viewports;
- check no major text overlap in the side panel.

## Open Questions

- Should `presentation.html` live at the study root or inside each run directory?
- Should the first production viewer include export-to-PDF instructions, or only HTML?
- Should summary Markdown be rendered with a tiny built-in parser or shown as formatted plain text first?
- Should the viewer include a side-by-side compare mode in the first release, or defer it?

## Recommended First Milestone

Build `sunlit.viewer` with:

- `render_study_viewer(output_dir: Path) -> Path`;
- static HTML template;
- baseline/with-scheme run switching;
- Map/Summary/Metadata/JSON tabs;
- no browser dependency;
- tests against the existing DXF example workflow.
